# 投研任务对照评测

本评测比较同一配置模型在无工具、固定工具流程和现有 Agent 三种条件下的表现。它是开发者编写、冻结的任务集，作者知道标准答案；20题保留集不属于外部独立盲测。任务总数较小，不据此宣称广泛统计显著优势。

## 任务与冻结

任务共30题：财报核验6题、模型适用性6题、同业比较4题、情景计算6题、缺失及期间边界5题、连续追问3题。10题开发集、20题保留集在调用模型前确定。财报题标准数值取自本地缓存原始财报字段，毛利按收入减成本独立计算；情景题为显式合成经营假设，不冒充真实公司披露参数。

`evals/research_tasks.jsonl` 保存问题、指定指标、预设工具调用和评分标准。`output/evaluation/freeze.json` 保存冻结时间、任务与工具快照哈希、工具定义哈希、数据文件及核心程序哈希。工具快照来自实际公开产品函数；不会为评测注入只用于回答标准答案的新工具。

## 三种条件

| 模式 | 提供的信息和执行方式 |
| --- | --- |
| direct | 相同模型、系统提示和用户题目；不提供工具结果，问题中明确给出的情景参数仍可见 |
| fixed | 按预定流程执行公开工具，再由模型回答；财报数据来自冻结工具输出，经营情景调用真实计算器 |
| agent | 调用现有 `run_agent`，由模型选择工具；与固定流程共用冻结工具输出和真实经营计算器 |

Agent 可调用冻结时的产品工具定义；快照未提供的实时行情等调用明确返回不可用，不会临时联网补数。两种有工具模式使用相同数据环境，但固定流程已预设相关工具，属于基准流程设计优势。无工具模式的信息较少，不能把它与 Agent 的差异直接归因于规划创新。

每个模型响应最多1600个输出token；Agent最多3轮工具调用，必要时再做一次无工具总结。单次API超时90秒，关闭SDK自动重试。保留首次运行结果，不静默重试失败题，也不根据保留集结果改题。3个连续追问题各有3轮请求，计入实际API调用数；任务数不等于API请求数。

## 评分

模型返回结构化JSON：任务指定的指标、数值、单位、状态、来源、适用性分类及四个明确的边界布尔字段。数值评分独立检查有限数字、单位换算和预定容差；缺失必须为null，不能是零或字符串。财报工具已有显示舍入，财报金额绝对容差默认100元、相对容差百万分之一；情景贡献默认绝对容差0.02元、相对容差百万分之一。

拒答检查要求 `status=abstain`、对应指标为null及边界字段正确。禁止结论按明确的结构化布尔字段判定，不用包含“不是”等自然语言的简单子串规则。模型适用性题同时核对经营类型枚举。多轮题自动评分最终一轮；完整各轮回答保留供人工核查。

来源检查要求引用本题实际可用来源URL的集合，或显式用户情景输入标识 `user:scenario`。冻结评分器中的 `source_supported` 实际只检查引用字符串集合相等，与数值正确性独立。因此该指标应称为“引用字符串匹配率”，不能称为“关键来源支持率”。它不证明引用语义支持了金额，也不证明数据商业授权或原始公告真实性。自然语言、来源语义及严重边界错误仍需要人工复核。

JSON格式错误、额外指标、未知来源、单位错误和非有限数值均不能通过。任务通过率以所有已运行任务为分母；API失败保留在分母中。数字正确率同时报告全部任务预期数字分母与成功解析后评分分母；拒答率保留全部应拒答题分母。引用字符串匹配率以全部已运行任务为分母。

## 只读审查与试跑复核

冻结后只读审查发现：固定流程在多轮题的每一轮都执行整题的全部 `fixed_calls`。例如T02第一轮已收到后续调价后的情景结果，T03第一轮已经收到后续切换公司的资料。这是未来轮信息预置，不能把这些多轮成绩作为同信息条件下的上下文保持或规划能力对照。只有单轮fixed与agent可作为同一工具数据环境下的对照；direct的信息更少。多轮结果保留并单独说明此限制，不删除、不重跑择优，也不调整冻结评分来改善结果。

首批9个任务（F01、S01、X01各三种模式）的人工复核：

| 运行 | 冻结评分失败原因 | 人工复核解释 |
|---|---|---|
| F01 direct | 缺数值、状态和来源不符 | 无工具条件下拒绝猜测当前缓存财报；任务未完成，不等同于编造金额 |
| F01 fixed | 两项金额错误 | 亿元换成元时缩小10倍，属于真实单位换算错误；尽管如此引用字符串仍匹配，说明来源项不能当事实支持率 |
| F01 agent | JSON解析失败 | 额外英文前缀违反JSON契约；内部JSON的营业收入和毛利换算后均在冻结容差内，应区分格式失败与金额错误 |
| S01 direct | 贡献数值错误 | 给出-125，正确值为5635元/吨铝，属于算术错误 |
| S01 agent | JSON解析失败 | value写成未求值的算式，JSON无效；note中的5635算术结果正确，结构化任务仍未完成 |
| X01三种模式 | 均通过 | 均拒绝在缺失成材率时填默认值，未编造经营贡献 |

F01 fixed显示：来源引用即便正确，输出金额仍可能严重错误。F01/S01 agent则显示自动数字正确率受到严格格式失败的影响。报告必须并列保留冻结任务通过率及人工错误分类，不能把两类问题合并解读为纯粹的金融计算能力差异。冻结自动评分只覆盖最终结构化字段，模型在note中自称“没有违规”不能替代人工事实核验。

审查没有修改冻结题、工具快照、工具定义或评分代码，也没有新增用于改善分数的测试题。A收入冲击核心由同一实现者自查，不计为独立代码审查。全量结果及实测表由完整运行产物更新。

评测运行期间另修复了生产环境外围的 `get_aluminum_profit` 和 `get_company_profile`：前者收窄为行业假设参考并验证日期、电价与价格，后者省略未经期间校验的画像金属占比。这两项不属于冻结快照可执行的财报/经营情景工具，不改变正在运行的90任务输入；不得将这些修复后的能力归入本轮90任务实测结论。冻结工具schema仍保留冻结时的版本，与当前生产说明可能不同，复现时须使用冻结文件。

## 运行

```powershell
python -m pytest -q tests/test_research_evaluation.py
python scripts/evaluate_research.py --freeze
python scripts/evaluate_research.py --pilot
python scripts/evaluate_research.py --all
python scripts/evaluate_research.py --summarize
```

冻结只执行一次，已有冻结文件时拒绝覆盖。试跑固定为F01财报、S01电解铝情景、X01缺失成材率，各执行三种模式，共9个任务。全量运行自动保留试跑及已有结果，继续补齐90个任务。真实API调用需配置现有模型API密钥。

`output/evaluation/runs/` 保存各任务原始回答、执行事件、状态、开始结束时间、耗时及实际token统计。`summary.json` 分别汇总整体、开发集和保留集。观察到的token与未知统计分开；没有经核实的供应商价格，因此金额成本保持未知，不预填估计费用。不保存密钥、认证头或API服务地址。

## 可观察回答复核

对90个任务的最终回答以及多轮题的全部前轮回答进行了逐项案头复核，共108轮。复核由本项目开发Agent辅助完成，属于开发者复核，不是外部客户试用或独立金融专家验收；没有要求或保存模型内部推理。复核只使用实际输出、冻结标准和工具事件，不改自动分数，也不另报“修正后通过率”。

| 模式 | 失败分类 | 复核结论 |
| --- | --- | --- |
| direct：23题未通过 | 11题缺财报输入；9题情景数值错误（M04另有模型分类错误）；3题仅来源不匹配 | 缺输入时多数拒绝猜测是合理边界，但任务未完成；部分note无依据声称“本地缓存无数据”，应表述为本条件未提供数据。情景题存在真实算术和量纲错误。 |
| fixed：6题未通过 | F01/F02/F05/C03金额错误；X03/X04仅来源不匹配 | 三道财报题把亿元换元时缩小10倍；C03结构化差额放大100倍且与note自相矛盾。X03/X04拒答结论正确，引用集合不满足冻结契约。 |
| agent：20题未通过 | 13题JSON解析失败；另有工具选择1题、指标键1题、分类字段1题、数值2题、仅来源2题 | JSON失败常为额外文字前缀，不可一律解释为金额错误；部分格式失败同时有取数失败或分类字段遗漏。S03/S05存在真实数值问题。 |

13个Agent格式失败为F01–F05、C03、C04、M02、M06、S01、S06、T01、T03。F01–F05、M02、S06可见正确金额，但额外前后文字破坏契约；M06还缺少规定的model分类字段。S01把算式直接写入JSON value，note中的5635元/吨铝正确。C03/C04/T03则同时未取得所需财报数据。上述分类有交叉，不能把13题都当作“只有格式问题”。

Agent事件记录中有67次对快照不支持工具的调用失败：`get_financial_indicators` 35次、`get_stock_fundamentals` 25次、`get_company_profile` 7次；成功调用财报利润工具11次、经营计算器9次。这反映本冻结可用性条件下的工具选择和预算消耗，不是生产数据服务发生67次网络故障。冻结schema保留全部工具，而快照仅支持限定财报和情景数据，也限制了这组结果的外推。

关键实例：

- `F01_fixed.json`、`F02_fixed.json`、`F05_fixed.json`：来源URL匹配但输出金额错10倍，说明引用匹配不能解释为事实有来源支持。
- `C03_fixed.json`：metrics给8173212520000元，正确差额约81732125200元；note列出了正确数量级，结构化数值仍错100倍。`C02_agent.json`的金额正确，但把要求的difference键写成“毛利差额”；note又误写“可跨期比较”，虽然上下文实际是同期间。
- `S03_agent.json`：漏掉原料损耗成本，metrics为1710、note说1200，正确约147.37元/吨成品；`S05_agent.json`的metrics为6200，而note正确计算1100。两者都是需修复的数值输出一致性问题。
- `M02_direct.json`：混淆干吨精矿、计价金属与回收金属，并在note中反复列出相互矛盾的结果；`S04_direct.json`把grade=0.3描述成0.3%，不能视为单纯格式错误。
- X03三种模式都合理拒绝不存在公司的利润估计，但使用了未被本题允许的 `user:scenario`；X04三种模式都拒绝用当前数据替代2099年财报，却未引用评分器要求的当前报表URL。这说明引用契约对明显拒答题存在过严或不合适要求，记录为下一版评测设计问题，本轮不改题、不改分。
- `T02_direct.json`与`T02_agent.json`最终delta=7200通过，但前两轮把应为30000/37200的贡献写成28000/35200，错误在相减时抵消。因此最终一轮通过不能代表三轮计算全对。fixed的三个数值正确，但其第一轮已看到第二轮调价结果，不能用于证明公平的连续推理优势。
- `T01_fixed.json`最终正确拒绝缺成本条件下比较铜毛利，前两轮营收金额却缩小10倍，note还将1941.78亿元误写成约1.94万亿元。`T03_agent.json`保留了切换到南山铝业的对象，但取数工具选择未取得数据；公司上下文保持与财报任务完成是两件不同的事。

本轮已观察到严重金额换算错误和过程输出不一致，因此没有达到计划中关键金额正确率至少95%的目标，也不能宣称“没有严重案例”。当前证据更支持将确定性工具结果作为数字主输出，并把模型组织语言和选择工具视为仍需改进的辅助环节。后续若修复，应冻结新的任务/程序版本并重跑，不覆盖本轮结果；客户节时、商业付费意愿及完整来源语义支持率仍未实测。
